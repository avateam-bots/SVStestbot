# Telegram-бот 1WIN India

Python 3.12, стандартная библиотека: сторонние зависимости не нужны.
Один контейнер, только long polling. Данные пользователей не сохраняются,
SQLite и /data не используются. Существующий README.md сохранён.

## Сценарий

/start → одно сообщение с кнопкой подтверждения → картинка с приветствием,
оффером и одной URL-кнопкой. Подтверждение обычное, без CAPTCHA.
Язык hi (включая hi-IN) выбирает хинди; любой другой или отсутствующий — английский.
Язык фиксируется на кнопке подтверждения до следующего /start.

## Изменение содержимого

Редактируйте config/content.json (UTF-8):
- bonus_url — полная ссылка, общая для двух языков;
- confirmation, confirm_button — сообщение и кнопка подтверждения;
- caption — приветствие и оффер под картинкой;
- bonus_button — подпись кнопки перехода;
- image — путь к локальной картинке внутри assets/.

Картинки: assets/welcome-en.png и assets/welcome-hi.png. Можно заменить
PNG или JPEG и изменить путь. Не более 10 МБ, сумма ширины и высоты до 10000,
отношение сторон до 20. Подпись — до 1024 символов.
Настройки и картинки включены в образ; изменения действуют после нового деплоя.
Ссылка сохранена как предоставлена. Параметры {{adset.id}} и похожие в ссылке
остаются рекламными шаблонами: Telegram-бот их автоматически не подставляет.

## Развертывание

1. Создайте бота через @BotFather и получите токен.
2. В панели платформы выберите этот репозиторий, Dockerfile в корне,
   контекст сборки — корень. Дополнительные сервисы и порты не нужны.
3. Добавьте секретную переменную окружения BOT_TOKEN в настройки запуска.
   Не добавляйте токен в Git, Dockerfile или настройки содержимого.
4. Запустите деплой. Команда запуска уже указана в Dockerfile.
5. Оставьте ровно один экземпляр бота. Откройте чат и проверьте /start.

Для локального Docker-запуска передайте BOT_TOKEN через окружение терминала:

```sh
docker build -t one-win-bot .
docker run --rm --name one-win-bot --env BOT_TOKEN one-win-bot
```

Для запуска без Docker (Python 3.12): python bot.py, с BOT_TOKEN в окружении.
Проверки без токена и сети: python -m unittest discover -s tests -v.
Бот удаляет прежний webhook без сброса ожидающих обновлений и начинает polling.
Ошибки токена и конфликт второго экземпляра завершают процесс.
Временные сетевые ошибки polling повторяются. Неудачное отдельное обновление
записывается в журнал без токена и пропускается; пользователь может повторить /start.
Состояние и offset находятся только в памяти; при перезапуске возможна повторная
обработка ещё не подтверждённых Telegram обновлений.

Методы API: https://core.telegram.org/bots/api
