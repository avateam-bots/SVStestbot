# Требования к проекту

## Запуск и сборка

- Использовать Python 3.12.
- Бот работает в одном контейнере и получает обновления Telegram только через long polling. Webhook’и и дополнительные контейнеры не использовать.
- `Dockerfile` находится в корне репозитория. Контекст сборки — корень репозитория.
- Образ содержит все зависимости бота. Сборка не требует `BOT_TOKEN` и других параметров окружения запуска.
- При запуске контейнера бот запускается автоматически, без ручных команд.
- Секреты, включая `BOT_TOKEN`, передаются через переменные окружения при запуске. Не сохранять их в репозитории или Docker-образе.

## Деплой

- Платформа автоматически собирает новый Docker-образ из репозитория и заменяет работающий контейнер.
- Платформа подключает постоянное хранилище к `/data`. Его содержимое сохраняется между перезапусками и деплоями. Настраивать подключение этого хранилища в проекте не требуется.

## Статические файлы и настройки

- Картинки, шаблоны, тексты, ссылки и другие несекретные настройки хранятся в репозитории и включаются в Docker-образ.
- Бот использует эти файлы непосредственно из образа. Изменения в репозитории должны вступать в силу после деплоя нового образа.

## Данные времени выполнения

- Использовать `/data` только для данных, создаваемых или изменяемых во время работы бота и требующих сохранения: данных пользователей, состояния бота, пользовательских загрузок и аналогичных данных.
- Если требуется постоянное хранение структурированных данных, использовать SQLite по пути `/data/bot.sqlite3`. Остальные постоянные данные времени выполнения хранить внутри `/data`.
- Подготовку хранилища и миграции выполнять автоматически при запуске с сохранением существующих данных.
- Не перезаписывать рабочую базу или другие накопленные данные начальными файлами из образа.
- Если постоянные данные не нужны, не создавать базу данных и не использовать `/data`.
